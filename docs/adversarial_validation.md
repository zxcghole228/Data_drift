# Adversarial Validation

Adversarial Validation превращает сравнение батчей во вспомогательную задачу
классификации: строкам Reference назначается метка `0`, строкам Current — `1`.
LightGBM пытается определить источник строки. Итоговый ROC-AUC рассчитывается
только по out-of-fold предсказаниям.

## Реализация

`adversarial_validate(reference, current, config)` выполняет
`StratifiedKFold(shuffle=True)` с фиксированным seed. В каждом фолде заново
создаётся единый sklearn `Pipeline`:

- числовые значения `±Infinity` заменяются на пропуски без изменения входных
  таблиц;
- медианная импутация чисел обучается только на train-части фолда;
- категориальные пропуски заполняются отдельным маркером внутри train pipeline;
- `OneHotEncoder(handle_unknown="ignore")` обучается только на train и поэтому
  корректно обрабатывает новую категорию в validation;
- затем обучается `LGBMClassifier` с фиксированным seed.

Служебная метка источника существует только как `y` и никогда не входит в
признаки. ID, целевая переменная основной модели и другие служебные поля должны
быть перечислены в `adversarial.exclude_columns`. Pipeline дополнительно
передаёт только признаки, прошедшие Schema Validation.

Для каждого фолда gain-важности one-hot столбцов суммируются обратно до
исходного признака, нормируются до суммы 1 и затем усредняются. Тип результата —
`mean_normalized_gain_across_folds`. Важность показывает полезность признака для
различения двух батчей, но не доказывает причину изменения.

## Интерпретация и ограничения

- ROC-AUC около `0.5` означает, что выбранный классификатор не смог надёжно
  различить батчи. Это не доказывает отсутствие любых видов дрейфа.
- Высокий ROC-AUC означает различимость входных данных, но не доказывает
  падение качества основной модели и не является автоматическим требованием
  переобучения.
- Порог ROC-AUC задаётся пользователем. Универсального порога для всех данных
  нет; при `null` возвращается численная метрика, но решения об алерте нет.
- Оценка на обучающих строках была бы оптимистичной, поэтому используется OOF.
- Если одинаковые сущности повторяются между фолдами, обычный StratifiedKFold
  может допустить утечку. Для таких данных потребуется идентификатор группы и
  групповой split; в версии 0.1 он ещё не реализован.
- Слишком маленькие батчи, `n_splits` больше размера меньшего источника и
  отсутствие подходящих признаков дают `skipped` с причиной.

Документация по предотвращению утечек:
<https://scikit-learn.org/stable/common_pitfalls.html>. Введение в Python API
LightGBM: <https://lightgbm.readthedocs.io/en/stable/Python-Intro.html>.
