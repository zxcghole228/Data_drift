# Размещение на GitHub

Подготовлены локальные ветки `main`, `mikhail` и `pavel`. Удалённый репозиторий ещё не создан, `origin` не настроен. В персональных ветках уже есть соответствующие недельные планы; оба файла также находятся в общей основе.

## Публикация подготовленной папки

1. Распаковать архив полностью. В папке `data-drift-guardian` сохранена служебная папка `.git`, содержащая локальную историю и ветки.
2. Создать на GitHub пустой репозиторий `data-drift-guardian`. Для открытой сдачи выбрать Public. Не добавлять README, `.gitignore` или лицензию через форму создания: начальный коммит уже подготовлен.
3. В терминале перейти в распакованную папку `data-drift-guardian` и проверить ветки:

```bash
git status
git branch
```

4. Подставить в следующую команду фактическую HTTPS-ссылку, которую показывает GitHub. `YOUR_GITHUB_LOGIN` — место для имени владельца, а не готовая ссылка:

```bash
git remote add origin https://github.com/YOUR_GITHUB_LOGIN/data-drift-guardian.git
git push -u origin main mikhail pavel
```

Git запросит авторизацию доступным в вашей среде способом. Не записывать токены в команды, README или конфигурацию репозитория.

Если GitHub CLI уже установлен и авторизован, вместо создания через сайт и добавления `origin` можно выполнить из папки проекта:

```bash
gh repo create data-drift-guardian --public --source=. --remote=origin
git push -u origin main mikhail pavel
```

## Проверка результата

- На GitHub есть все три ветки, основной выбрана `main`.
- В `mikhail` открывается `docs/plans/mikhail.md`.
- В `pavel` открывается `docs/plans/pavel.md`.
- README и планы корректно отображаются на русском языке.

Чтобы Павел мог отправлять изменения, владелец должен добавить его фактический GitHub-аккаунт в collaborators. Это отдельное действие с проверкой аккаунта; приглашение пока не отправлялось.

После клонирования опубликованного репозитория рабочая ветка выбирается командой `git switch mikhail` или `git switch pavel`; Git обычно создаёт локальную ветку из одноимённой удалённой.
