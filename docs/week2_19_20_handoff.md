## Что принято

- CLI читает CSV/Parquet и YAML, сохраняет строгий JSON, поддерживает
  `--overwrite`, `--debug`, `--fail-on-alert` и опциональный автономный HTML.
- HTML и Streamlit используют сохранённый `AnalysisResult`, показывают
  `effective_config`, источники порогов, Cramér's V, категориальные диагностики
  и стратегию ML-split без повторной статистической логики.
- Streamlit запускает тяжёлый анализ только по кнопке, помечает результат stale,
  фильтрует готовые данные и выдаёт тот же JSON/HTML для скачивания.
- Docker использует Python 3.13, `libgomp1`, непривилегированного пользователя
  с UID 10001 и healthcheck `/_stcore/health`; локально получены `healthy` и
  ответ `ok`.
- GitHub Actions проверяет импорты, полный `pytest`, сборку образа, non-root
  пользователя и healthcheck контейнера.

## Проверенные ошибки и частичные результаты

Полный набор тестов покрывает:

- отсутствующий входной файл и обязательные CLI-аргументы;
- неверный YAML и ошибочную конфигурацию;
- несовместимую схему и header-only/пустой Current;
- существующий, совпадающий или недоступный output path и атомарность записи;
- all-missing, константы, бесконечности и неприменимые статистические проверки;
- отсутствующий group column и невозможный grouped split;
- отсутствие `NaN`/`Infinity` в JSON и неизменность входных DataFrame.

Ошибка запуска, структурированный частичный результат, `skipped`,
статистический алерт и инфраструктурная ошибка сохраняются как разные состояния.

## Как проходит один анализ

`CLI/Streamlit` загружает файлы через ingestion, затем конфигурация и schema
определяют допустимые признаки. Data Quality считает пропуски, дубликаты,
бесконечности и диапазоны. Pipeline вызывает числовые/категориальные методы и
опциональный Adversarial Validation, применяет BH и собирает единый
`AnalysisResult`. Reporting и Streamlit только отображают этот результат и
строят графики по тем же входным DataFrame.

Статистическая интерпретация остаётся ограниченной:

- p-value отвечает не на тот же вопрос, что Cramér's V или distance-метрика;
- Feature Importance показывает вклад в различение батчей, но не причину;
- высокий OOF AUC показывает различимость Reference/Current, но без target не
  доказывает concept drift или падение качества основной модели;
- BH контролирует семейство статистических решений, но не гарантирует отсутствие
  ложных тревог в каждом отдельном запуске;
- мощность зависит от размера батча и величины сдвига.

## Что намеренно не закрыто

До дедлайна 27.09 остаются:

1. итоговый текст проекта в HTML или PDF;
2. скринкаст работы продолжительностью 2–5 минут;
3. проверка открытого доступа ко всем итоговым ссылкам;
4. финальный clean-clone smoke test и, при необходимости, GitHub tag/release;
5. неблокирующая визуальная полировка широких HTML/Streamlit-таблиц;
6. online-мониторинг: источник последовательных батчей, жизненный цикл
   Reference, расписание/триггер, хранение истории и доставка алертов.

Online-мониторинг не входит в этот release candidate и должен быть оформлен
отдельным следующим планом. До появления этого слоя проект корректно описывать
как воспроизводимый offline/batch-анализатор, а не как готовый continuously
running production-сервис.
