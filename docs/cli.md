# Командный интерфейс Data Drift Guardian

Контракт согласован 15.09.2026. Первая реализация запланирована на 16.09.2026.
CLI использует контракт результата `0.2` и сохраняет совместимость с YAML
версии `0.1`, которую обеспечивает общий загрузчик конфигурации.

## Назначение

Командный интерфейс запускает полный анализ двух локальных таблиц без
Streamlit и сохраняет структурированный `AnalysisResult` в JSON. Он предназначен
для ручного запуска, shell-скриптов и CI.

CLI является только оркестратором существующих компонентов:

1. загружает Reference и Current через `load_table`;
2. загружает и валидирует YAML через `load_config`;
3. один раз вызывает `analyze(reference, current, config)`;
4. печатает краткую сводку;
5. атомарно сохраняет полный результат.

CLI не реализует собственные статистические правила, не выбирает пороги и не
пересчитывает поля результата. Источником истины остаётся публичная функция
`analyze`.

## Основной вызов

```bash
python -m data_drift_guardian \
  --reference data/generated/none/reference.csv \
  --current data/generated/none/current.csv \
  --config configs/default.yaml \
  --json-output outputs/none.json
```

Reference и Current могут иметь формат CSV или Parquet. Формат определяется
существующим `load_table` по расширению файла.

## Аргументы

| Аргумент | Обязательный | Назначение |
| --- | --- | --- |
| `--reference PATH` | Да | Путь к Reference в формате CSV или Parquet |
| `--current PATH` | Да | Путь к Current в формате CSV или Parquet |
| `--config PATH` | Да | Путь к YAML-конфигурации анализа |
| `--json-output PATH` | Да | Путь для полного JSON-результата |
| `--html-output PATH` | Нет | Путь для автономного HTML-отчёта; подключается вместе с реализацией HTML-экспорта 17.09 |
| `--overwrite` | Нет | Разрешить замену существующих output-файлов |
| `--fail-on-alert` | Нет | Завершиться с кодом `2`, если анализ создал хотя бы один алерт |
| `--debug` | Нет | Показать полный traceback при ошибке запуска |
| `--help` | Нет | Показать справку и завершиться с кодом `0` |

`--html-output` зарезервирован этим контрактом, но не должен появляться как
работающая возможность до реализации `reporting.export_html`. CLI не должен
создавать пустой или фиктивный HTML-файл.

## Коды завершения

| Код | Значение |
| ---: | --- |
| `0` | Анализ успешно выполнен. Наличие алертов без `--fail-on-alert` не является ошибкой программы |
| `1` | Ошибка аргументов, чтения файлов, YAML, конфигурации, анализа или записи результата |
| `2` | Анализ успешно выполнен, есть алерты и явно передан `--fail-on-alert` |

Стандартный `argparse` использует код `2` для ошибки аргументов. В этом CLI
ошибка разбора команды должна возвращать `1`, потому что код `2` однозначно
зарезервирован для бизнес-алерта. Вызов `--help` остаётся успешным и возвращает
`0`.

При `--fail-on-alert` результат сначала полностью сохраняется, и только после
этого процесс завершается с кодом `2`. Это позволяет CI и пользователю изучить
причины алерта.

## Вывод в stdout и stderr

После успешного анализа stdout содержит короткую человекочитаемую сводку:

```text
Анализ завершён
Статус: warning
Проанализировано признаков: 3
Пропущено признаков: 0
Алертов: 2
JSON: outputs/combined.json
```

Полный `AnalysisResult` в stdout не печатается. Он сохраняется в JSON-файл.

Обычная пользовательская ошибка выводится в stderr без traceback:

```text
Ошибка: файл Reference не найден: data/reference.csv
```

С флагом `--debug` в stderr дополнительно выводится полный traceback. Этот флаг
не изменяет код завершения и не скрывает короткое сообщение об ошибке.

## Формат JSON

JSON-файл содержит результат `analyze` без изменения структуры:

- кодировка UTF-8;
- `ensure_ascii=False`;
- отступ `indent=2`;
- сериализация с `allow_nan=False`;
- `contract_version == "0.2"`;
- `effective_config` содержит фактически применённую нормализованную
  конфигурацию;
- значения `NaN` и `Infinity` не допускаются.

CLI не должен читать исходный YAML второй раз для формирования отчёта и не
должен подменять `effective_config` значениями по умолчанию.

## Политика output-файлов

Перед тяжёлым анализом CLI проверяет все запрошенные output-пути.

- Недостающие родительские директории создаются автоматически.
- Существующий файл без `--overwrite` не изменяется, команда завершается с
  кодом `1`.
- `--overwrite` явно разрешает замену существующего результата.
- JSON сначала полностью сериализуется в памяти с `allow_nan=False`.
- Затем содержимое записывается во временный файл в той же директории.
- Успешно записанный временный файл заменяет целевой через `os.replace`.
- При любой ошибке временный файл удаляется, а старый целевой файл остаётся
  неизменным.
- После ошибки не должен оставаться частично записанный результат.

Проверку существующего output-файла следует выполнять до загрузки данных и
запуска статистики, чтобы не тратить время на анализ, результат которого всё
равно нельзя сохранить.

## Пользовательские поля контракта 0.2

Краткий stdout не перегружается внутренними `details`. Полный JSON сохраняет
все поля без потерь. В последующих HTML- и Streamlit-интерфейсах используются
следующие правила отображения:

| Поле | Представление |
| --- | --- |
| `contract_version` | Заголовок или метаданные результата |
| `effective_config` | Полностью в JSON; отдельный раскрываемый блок в UI/HTML |
| `threshold` | Основная таблица метрик |
| `details.threshold_source` | Отдельная колонка «Источник порога» |
| `details.resolved_threshold` | Остаётся в JSON, поскольку дублирует `threshold` |
| `details.cramers_v` | Основная таблица рядом с результатом χ² |
| Число новых, исчезнувших и pooled-категорий | Диагностический блок категориального признака |
| Полные списки категорий и их доли | Раскрываемые подробности и JSON |
| `adversarial.split_strategy` | Основной раздел Adversarial Validation |
| `adversarial.group_column`, `adversarial.n_groups` | Подпись к результату ML-проверки |
| `reason` для `skipped`/`error` | Всегда непосредственно рядом со статусом |

## Примеры

Контрольный сценарий без внесённого дрейфа:

```bash
python -m data_drift_guardian \
  --reference data/generated/none/reference.csv \
  --current data/generated/none/current.csv \
  --config configs/default.yaml \
  --json-output outputs/none.json
```

Сценарий с комбинированным сдвигом и кодом `2` при алерте:

```bash
python -m data_drift_guardian \
  --reference data/generated/combined/reference.parquet \
  --current data/generated/combined/current.parquet \
  --config configs/default.yaml \
  --json-output outputs/combined.json \
  --fail-on-alert
```

Явная замена ранее сохранённого результата:

```bash
python -m data_drift_guardian \
  --reference data/generated/none/reference.csv \
  --current data/generated/none/current.csv \
  --config configs/default.yaml \
  --json-output outputs/none.json \
  --overwrite
```

Диагностический режим:

```bash
python -m data_drift_guardian \
  --reference data/reference.csv \
  --current data/current.csv \
  --config configs/default.yaml \
  --json-output outputs/result.json \
  --debug
```

## Отличие библиотеки от CLI

Библиотечные функции сообщают об ошибке исключением Python, чтобы вызывающий
код мог самостоятельно выбрать стратегию обработки. CLI является границей
приложения: он перехватывает ошибку, переводит её в короткое сообщение для
человека и возвращает документированный код процесса.

Статистический алерт не является исключением. Анализ с алертом считается
успешным вычислением и по умолчанию возвращает `0`. Код `2` появляется только
по явному запросу пользователя через `--fail-on-alert`.

## Критерии приёмки реализации 16.09

Реализация считается готовой, если:

- команда запускается через `python -m data_drift_guardian`;
- CSV и Parquet поддерживаются для обеих таблиц;
- YAML проходит через существующий `load_config`;
- `analyze` вызывается ровно один раз;
- stdout содержит краткую сводку, а JSON — полный результат;
- JSON проходит `json.dumps(result, allow_nan=False)`;
- отсутствующая директория output создаётся;
- существующий файл защищён без `--overwrite`;
- запись JSON атомарна;
- обычная ошибка не печатает traceback;
- `--debug` печатает traceback;
- алерт возвращает `0` без `--fail-on-alert` и `2` с ним;
- неправильные аргументы возвращают `1`;
- после ошибки отсутствует повреждённый output-файл.

Минимальный набор автоматических проверок:

| Сценарий | Ожидаемый результат |
| --- | --- |
| `--help` | Код `0`, справка в stdout |
| Недостающий обязательный аргумент | Код `1`, понятная ошибка без traceback |
| Корректные CSV | Код `0`, валидный JSON |
| Корректные Parquet | Код `0`, валидный JSON |
| Отсутствующий входной файл | Код `1`, output не создан |
| Некорректный YAML | Код `1`, output не создан |
| Несовместимая схема | Структурированный результат согласно поведению `analyze`, без падения CLI |
| Существующий output без `--overwrite` | Код `1`, файл не изменён |
| Существующий output с `--overwrite` | Код `0` либо `2`, файл заменён полностью |
| Алерт без `--fail-on-alert` | Код `0`, JSON сохранён |
| Алерт с `--fail-on-alert` | Код `2`, JSON сохранён |
| Несериализуемый результат | Код `1`, частичный файл отсутствует |
| Ошибка с `--debug` | Код `1`, traceback присутствует |

- `src/data_drift_guardian/__main__.py`;
- `tests/integration/test_cli.py`;
