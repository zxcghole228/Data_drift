# Архитектура Data Drift Guardian

Data Drift Guardian использует одно статистическое ядро для offline-анализа,
CLI, HTML-отчёта, Streamlit и online micro-batch мониторинга. Интерфейсы не
пересчитывают метрики самостоятельно: они отображают единый `AnalysisResult`.

## Поток offline-анализа

1. `ingestion.py` читает CSV/Parquet в `pandas.DataFrame`.
2. `config.py` загружает и валидирует YAML.
3. `schema.py` определяет совместимые признаки и нарушения схемы.
4. `quality.py` проверяет пропуски, дубликаты, Infinity и Min/Max.
5. `drift/` рассчитывает KS, Wasserstein, χ², Cramér's V, PSI и JS.
6. `adversarial.py` при включении строит OOF LightGBM-классификатор.
7. `alerts.py` применяет пороги и формирует объяснимые алерты.
8. `pipeline.py` собирает JSON-безопасный результат контракта `0.2`.
9. CLI, HTML и Streamlit представляют тот же результат.

Ошибка одного признака не отменяет анализ остальных. Входные таблицы не
изменяются, а `skipped` и `error` не превращаются в успешный статус.

## Online-слой

Online API добавляет транспорт и persistent-состояние вокруг того же pipeline:

1. оператор регистрирует и активирует Reference;
2. API принимает отдельные события или готовые батчи;
3. события сохраняются в SQLite и формируют непересекающиеся окна;
4. готовое окно становится Current для общего `analyze`;
5. Run, полный результат, алерты и доставки сохраняются в SQLite;
6. JSONL/webhook получают уведомление независимо от успешности самого Run;
7. Streamlit читает состояние и историю без повторного анализа;
8. запаздывающий Feedback позволяет оценить Accuracy и ROC-AUC основной
   модели, если эта проверка включена.

API запускается одним worker: горизонтальное масштабирование SQLite-версии не
поддерживается. Полный HTTP-контракт и правила идемпотентности описаны в
[`online_monitoring.md`](online_monitoring.md).

## Основные инварианты

- Schema Validation выполняется до статистических тестов.
- NaN остаются видимыми Data Quality и исключаются из обычных drift-метрик.
- Числовые бины определяются Reference и одинаково применяются к Current.
- p-value и величина эффекта не смешиваются; для KS/χ² доступна поправка BH.
- Порог Wasserstein задаётся в единицах конкретного признака.
- Предобработка Adversarial Validation обучается внутри каждого train-fold.
- ID, target и служебная метка источника не попадают в ML-признаки.
- Любой итоговый результат сериализуется с `allow_nan=False`.
- Повтор одного `event_id`/`batch_id` не создаёт повторный Run.
- Ошибка доставки алерта не уничтожает сохранённый результат анализа.

## Границы решения

Data drift означает изменение `P(X)`. Concept drift означает изменение
`P(y|X)` и не доказывается только входными признаками. Высокий PSI, значимый
KS/χ² или высокий adversarial ROC-AUC являются сигналами для расследования.
Проверка качества модели по Feedback приближает обнаружение concept drift, но
также не устанавливает его причину автоматически.

В учебную версию не входят автоматическое переобучение, автоматическая замена
Reference, Kafka, распределённая очередь, аутентификация и горизонтальное
масштабирование. Для внешнего production-развёртывания сервису необходимы API
gateway/reverse proxy, TLS, аутентификация, rate limiting и управляемое
хранилище.

Детали методов находятся в [`methods.md`](methods.md), структуры данных — в
[`contracts.md`](contracts.md), запуск — в [`deployment.md`](deployment.md).
