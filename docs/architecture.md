## Решения, которые нужно закрепить при реализации

- Проверять схему до запуска статистики. Несовместимый тип не исправлять молча.
- Входные DataFrame не изменять на месте. Пропуски и дубликаты остаются видимыми в отчёте качества.
- NaN учитывать в Data Quality; числовые тесты применять к пригодным конечным значениям с указанием их числа. Недостаток данных обозначать явно.
- Бины числовых распределений строить по Reference и применять к Current. Покрывать хвосты, новые значения и вырожденный Reference. Для категорий использовать совместимое пространство значений.
- Для χ² использовать таблицу частот двух выборок; учитывать ограничения при малых ожидаемых частотах. Выбранная обработка редких категорий должна быть описана и протестирована.
- KS предназначен для сравнения непрерывных распределений: для дискретных и сильно округлённых данных нужно оговорить ограничения интерпретации p-value. [SciPy: KS](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ks_2samp.html).
- Различать статистическую значимость и величину сдвига. Предусмотреть поправку на множественные проверки для применимых p-value. Пороги эффектов сначала исследовать на сценариях без дрейфа и с дрейфом.
- В задании запрошена JS divergence. `scipy.spatial.distance.jensenshannon` возвращает её квадратный корень: для divergence результат возводится в квадрат, основание логарифма фиксируется. [SciPy: Jensen–Shannon](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.distance.jensenshannon.html).
- ROC-AUC Adversarial Validation получать на отложенных наблюдениях; предобработку обучать внутри train-части разбиения. Служебный индикатор выборки, ID и целевая переменная не должны попадать в признаки классификатора. При повторяющихся объектах учитывать группы при разбиении. [scikit-learn: утечки данных](https://scikit-learn.org/stable/common_pitfalls.html).
- Высокий ROC-AUC — свидетельство различимости выборок выбранным классификатором; ROC-AUC около 0.5 сам по себе не доказывает отсутствие всех видов дрейфа.

## Как объяснять результат

Data drift относится к изменениям распределения признаков, concept drift — к изменениям связи признаков и целевой переменной. Без целевой переменной в продакшене система не может напрямую установить падение качества основной модели. Поэтому алерт рекомендует исследовать сдвиг и проверить качество модели, а необходимость переобучения требует отдельного решения. [Evidently: concept drift](https://www.evidentlyai.com/ml-in-production/concept-drift).

Результат ошибки или пропущенной проверки не превращается в зелёный статус. Причина недоступности показывается пользователю. Для итогового отчёта необходимо также объяснить, какие сценарии метод способен пропустить.
