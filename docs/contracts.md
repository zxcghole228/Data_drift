# Общий контракт, версия 0.2

Публичный offline-контракт имеет версию `0.2`. Загрузчик принимает конфигурации
`0.1` и `0.2`, но всегда возвращает нормализованный `effective_config` версии
`0.2`. Изменения контракта должны одновременно отражаться в этом документе,
`contracts.py`, конфигурации и использующих их модулях.

## Вход

```python
analyze(reference: pandas.DataFrame,
        current: pandas.DataFrame,
        config: Mapping[str, Any] | None = None) -> AnalysisResult
```

Первые два аргумента обязательны. Конфигурация задаёт ожидаемые колонки, семантические типы, диапазоны и пороги. При `config=None` реализация использует документированные параметры по умолчанию и выводит только семантические типы признаков из Reference. Диапазоны и пороги при этом не выводятся из наблюдавшихся минимумов, максимумов или результатов тестов.

- Reference и Current могут иметь разное число строк.
- Строки не сопоставляются по индексам; это сравнение распределений.
- Входные объекты не изменяются.
- Дублирующиеся названия колонок и пустые выборки получают явное описание ошибки в разделе `schema`.
- Неверный Python-тип входа — `TypeError`; неверная конфигурация — `ValueError`.
- Проблемы содержимого допустимого DataFrame возвращаются в структурированном отчёте. Неприменимые вычисления помечаются `skipped` с причиной.
- Ошибка одного признака не отменяет анализ остальных признаков, если они прошли проверку схемы.

## Схема и совместимость типов

Поддерживаются два семантических типа: `numeric` и `categorical`.

- Любой вещественный pandas dtype, для которого `is_numeric_dtype` возвращает `True`, совместим с `numeric`, кроме `bool`. Комплексные значения не поддерживаются, потому что KS и одномерный Wasserstein требуют упорядочиваемую числовую ось.
- `object`, pandas `string`, `category` и `bool` совместимы с `categorical`.
- `datetime`, вложенные объекты и остальные неподдерживаемые dtype не преобразуются молча: признак помечается как несовместимый или пропущенный.
- Различие физических числовых dtype (`int64`, nullable `Int64`, `float64`) само по себе не является ошибкой схемы. Фактические dtype обеих таблиц сохраняются в `details`.
- Если `allow_extra_columns: false`, лишние колонки являются нарушением схемы. Они не включаются в drift-анализ.
- Отсутствующий обязательный признак является нарушением схемы; этот признак получает `skipped`, но совместимые признаки можно анализировать дальше.

Schema Validation проверяет тип, наличие и допустимость признака. Он не исправляет данные и не выполняет неявное приведение типов.

## Пропуски и невалидные числовые значения

- Доли `NaN`/`None` всегда отражаются в Data Quality для Reference и Current.
- Обычные drift-тесты сравнивают распределения непустых значений; пропуски из них исключаются. Таким образом, изменение пропусков остаётся отдельным объяснимым сигналом.
- Положительная и отрицательная бесконечность считаются невалидными числовыми значениями, отражаются в Data Quality и исключаются из числовых drift-тестов.
- Число исходных и использованных наблюдений сохраняется в `details`. Если пригодных наблюдений недостаточно, результат — `skipped`, а не «дрейфа нет».
- Для KS и Wasserstein требуется минимум два конечных значения в каждой выборке.
- Adversarial Validation заменяет бесконечности на пропуски без обучения,
  а медианную импутацию чисел, заполнение категориальных пропусков и one-hot
  кодирование обучает отдельно внутри train-части каждого фолда. Новые
  validation-категории игнорируются кодировщиком. Подробности находятся в
  [`methods.md`](methods.md).

## Правила Data Quality

- Доля пропусков считается как число `NaN`/`None`/`pd.NA` относительно общего числа строк таблицы. Рост пропусков равен разности долей Current и Reference, умноженной на 100, и измеряется в процентных пунктах.
- Для признака с `nullable: false` допустимая доля пропусков равна нулю; наличие пропуска считается критическим нарушением.
- Дубликатами считаются повторные полные строки после первого вхождения, аналогично `DataFrame.duplicated(keep="first")`. Индекс DataFrame не участвует, знаменатель доли — общее число строк.
- Положительная и отрицательная бесконечность учитываются отдельно от пропусков и считаются критическим нарушением.
- Проверки `min` и `max` выполняются только по конечным значениям. Значения, равные границам, допустимы; нарушениями считаются значения строго ниже `min` или выше `max`.
- Пороговые правила срабатывают только при строгом превышении порога. Значение, равное максимально допустимому, считается корректным.
- Превышение порогов пропусков и дубликатов имеет статус `warning`; нарушение `nullable: false`, границ `min/max` или наличие бесконечностей — `critical`.

## Результат

`AnalysisResult` — обычный словарь Python с объявлениями `TypedDict`. Он должен сериализоваться через `json.dumps(result, allow_nan=False)`. Значения NaN/Infinity в выходном JSON заменяются на `None` вместе с объяснением; числовые скаляры numpy переводятся в обычные типы Python.

| Поле | Содержание |
| --- | --- |
| `contract_version` | Строка `0.2` |
| `effective_config` | Полная JSON-safe конфигурация 0.2, фактически использованная вызовом |
| `metadata` | Число строк выборок и seed |
| `schema` | Статус, отсутствующие/лишние колонки и несовпадения типов |
| `quality` | Проверки уровня таблицы и отдельных признаков |
| `drift` | Результаты по признакам и использованные методы |
| `adversarial` | Статус, ROC-AUC, порог, значения по фолдам, важности и объяснение |
| `alerts` | Список сработавших правил: источник, признак, проверка, серьёзность, текст |
| `summary` | Общий статус, количество алертов, проверенных и пропущенных признаков |

`CheckResult` содержит `name`, `status`, `value`, `threshold`, `p_value`, `adjusted_p_value`, `alert`, `reason`, `details`. Для метрики без p-value это поле равно `None`. В `details` помещаются размеры выборок, фактические dtype, границы бинов и другие сведения, нужные для проверки расчёта.

## Значение статусов

| Статус | Значение |
| --- | --- |
| `ok` | Проверка выполнена без вычислительной ошибки; если правило задано, оно не сработало |
| `warning` | Сработало предупреждение |
| `critical` | Сработало критическое правило |
| `skipped` | Проверку не выполняли или она неприменима; причина обязательна |
| `error` | Проверку не удалось выполнить из-за ошибки; причина обязательна |

`alert=True` — правило сработало; `False` — применимое правило проверено и не сработало; `None` — решения по правилу нет, например не задан порог или проверка пропущена. Отсутствие решения нельзя считать подтверждением стабильности.

Поэтому допустим результат `status="ok"`, `value=<число>`, `threshold=None`, `alert=None`: метрика успешно вычислена, но правило алерта для неё не настроено.

Статистические результаты и Data Quality имеют отдельные разделы. Увеличение доли пропусков считается в процентных пунктах: рост с 2% до 7% равен 5 п.п.

Для сводки приоритет состояний: `error`, `critical`, `warning`, затем `ok`. Если ничего не проверено, `skipped`. Частичные пропуски сохраняются в счётчике и пояснениях независимо от общего статуса. `has_alerts` означает только наличие сработавших правил, а не полноту анализа.

## Стартовая конфигурация

`configs/default.yaml` — пример для синтетических данных, а не универсальная
схема произвольного датасета. Его структура формально описана `AnalysisConfig`
и вложенными `TypedDict` в `contracts.py`. Пороги качества иллюстративные.
Незаданные пороги расстояний и ROC-AUC имеют значение `null`: соответствующие
численные результаты можно вычислить, но флаг дрейфа без правила выставлять
нельзя.

Загрузчик принимает YAML версии 0.1 и 0.2. Конфигурация 0.1 нормализуется до
0.2: добавляются пустое `drift.feature_thresholds` и
`adversarial.group_column: null`. В `effective_config` всегда находится полный
нормализованный документ 0.2. Поэтому старые CLI/notebook/UI-вызовы остаются
рабочими, а потребители результата видят параметры фактического запуска.

Декларации `TypedDict` сами по себе не выполняют runtime-валидацию. Загрузчик конфигурации обязан проверить обязательные ключи, типы и ограничения значений до запуска анализа и выбросить `ValueError` для некорректной конфигурации.

## Семейство множественных проверок

При `multiple_testing: bh` одно семейство состоит из всех успешно рассчитанных
p-value KS и χ² внутри одного вызова `analyze`. Пропущенные и ошибочные проверки
не входят в семейство. В `p_value` сохраняется исходное значение, в
`adjusted_p_value` — монотонная поправка Benjamini–Hochberg. Решение сравнивает
скорректированное значение с `alpha`; информация о размере семейства и ранге
сохраняется в `details`. При `multiple_testing: none` решение принимается по
исходному p-value.

`alpha` и BH остаются общими для одного семейства всех пригодных KS/χ² одного
вызова `analyze`. Отдельный alpha по признакам не поддерживается: он изменил бы
статистическую модель семейства и потребовал бы отдельного контракта.

## Пороги distance-метрик

Для Wasserstein, PSI и JS действует единый приоритет:

1. ключ метода в `drift.feature_thresholds.<feature>`;
2. `drift.distance_thresholds.<method>`;
3. отсутствие решения (`None`).

Явный `null` на уровне признака имеет приоритет над общим значением и отключает
автоматическое решение только для этой пары «признак–метод». Пример:

```yaml
drift:
  distance_thresholds:
    wasserstein: null
    psi: 0.20
    js: 0.10
  feature_thresholds:
    age:
      wasserstein: 3.0
    income:
      wasserstein: 10000.0
      psi: null
```

Порог срабатывает только при строгом `value > threshold`; равенство не создаёт
алерт. Численное равенство проверяется с допуском `1e-12`, чтобы результат вроде
`3.0000000000000004` не считался превышением теоретической границы `3.0`. В
`CheckResult.details` сохраняются `resolved_threshold` и
`threshold_source` со значением `feature`, `global` либо `not_configured`.
Wasserstein измеряется в единицах признака, поэтому один абсолютный порог для
возраста и дохода обычно не имеет содержательного смысла. PSI и JS безразмерны,
но их границы всё равно требуют калибровки на конкретных данных.

## Adversarial Validation

Adversarial Validation возвращает ROC-AUC, рассчитанный по объединённым
отложенным предсказаниям, отдельные значения по фолдам и усреднённые
нормированные gain-важности. Поле `threshold` повторяет настроенный порог
ROC-AUC. Если порог равен `null`, численная оценка вычисляется, но `alert`
остаётся `None`.

При `adversarial.group_column: null` используется `StratifiedKFold`. При имени
колонки применяется `StratifiedGroupKFold`; идентификатор извлекается до отбора
model features и никогда не передаётся модели. Поля `split_strategy`,
`group_column` и `n_groups` описывают фактическое разбиение. Отсутствующая
колонка, пропущенный ID или недостаток групп дают `skipped` с причиной.

Структурный пример результата:
[`examples/analysis_result_v0.2.json`](examples/analysis_result_v0.2.json).
